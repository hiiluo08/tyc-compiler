# Codebase Structure

**Analysis Date:** 2026-05-07

## Directory Layout

```text
tyc-compiler/
├── run.py                       # Cross-platform setup/build/test entrypoint
├── src/                         # Compiler implementation
│   ├── grammar/                 # ANTLR grammar + lexer error helpers
│   ├── astgen/                  # Parse tree -> AST mapping
│   ├── utils/                   # AST nodes, visitor contracts, parser error listener
│   ├── semantics/               # Static semantic checking and error types
│   ├── codegen/                 # AST -> Jasmin code generation stack
│   └── runtime/                 # JVM runtime assets and generated outputs
├── tests/                       # End-to-end and phase-level test suites + harness
├── build/                       # Generated ANTLR lexer/parser/visitor modules
├── external/                    # Tooling assets (ANTLR jar)
├── reports/                     # HTML test reports generated by run.py commands
└── gsd/                         # Isolated web-runner variant workspace and planning
    ├── WEBAPP_SPEC.md
    ├── WORKFLOW_AUTOMATION_PROMPT.md
    └── .planning/codebase/      # Architecture/structure docs for GSD planning
```

## Directory Purposes

**`src/grammar/`:**
- Purpose: Source-of-truth language grammar and lexer exceptions.
- Contains: `TyC.g4`, `lexererr.py`.
- Key files: `src/grammar/TyC.g4`, `src/grammar/lexererr.py`.

**`src/astgen/`:**
- Purpose: AST generation phase.
- Contains: `ASTGeneration` visitor implementation.
- Key files: `src/astgen/ast_generation.py`.

**`src/utils/`:**
- Purpose: Shared compiler contracts.
- Contains: AST class hierarchy, visitor interface, parser error listener.
- Key files: `src/utils/nodes.py`, `src/utils/visitor.py`, `src/utils/error_listener.py`.

**`src/semantics/`:**
- Purpose: Static analysis and semantic diagnostics.
- Contains: checker logic and exception classes.
- Key files: `src/semantics/static_checker.py`, `src/semantics/static_error.py`.

**`src/codegen/`:**
- Purpose: Lower AST to Jasmin bytecode representation.
- Contains: high-level generator, emitter, frame tracking, symbols, IO mapping.
- Key files: `src/codegen/codegen.py`, `src/codegen/emitter.py`, `src/codegen/frame.py`, `src/codegen/io.py`, `src/codegen/utils.py`.

**`src/runtime/`:**
- Purpose: Runtime library and generated output target.
- Contains: `io.java`, `jasmin.jar`, generated `*.j`, generated `*.class`.
- Key files: `src/runtime/io.java`, `src/runtime/jasmin.jar`.

**`tests/`:**
- Purpose: Functional verification across phases.
- Contains: lexer/parser/AST/checker/codegen tests and wrappers.
- Key files: `tests/utils.py`, `tests/test_checker.py`, `tests/test_codegen.py`.

**`gsd/`:**
- Purpose: Isolated workspace for web-compiler variant.
- Contains: variant specs and GSD planning artifacts.
- Key files: `gsd/WEBAPP_SPEC.md`, `gsd/.planning/codebase/ARCHITECTURE.md`, `gsd/.planning/codebase/STRUCTURE.md`.

## Key File Locations

**Entry Points:**
- `run.py`: Primary command dispatcher for build/setup/test flows.
- `tests/utils.py`: Programmatic compiler pipeline wrappers used by tests.

**Configuration:**
- `requirements.txt`: Python dependencies.
- `src/grammar/TyC.g4`: Language and lexer behavior configuration.

**Core Logic:**
- `src/astgen/ast_generation.py`: Parse-tree to AST transformation.
- `src/semantics/static_checker.py`: Type/scope checking and inference.
- `src/codegen/codegen.py`: AST traversal and Jasmin emission orchestration.

**Testing:**
- `tests/test_lexer.py`: Lexer behavior checks.
- `tests/test_parser.py`: Parser behavior checks.
- `tests/test_ast_gen.py`: AST string-shape checks.
- `tests/test_checker.py`: Semantic checking result checks.
- `tests/test_codegen.py`: Runtime output checks.

## Naming Conventions

**Files:**
- Python modules use `snake_case.py`: `static_checker.py`, `ast_generation.py`.
- Test files use `test_*.py`: `test_codegen.py`.

**Directories:**
- Phase-oriented folders under `src/`: `astgen`, `semantics`, `codegen`.
- Variant-isolation folder under `gsd/` for all web-runner work.

## Where to Add New Code

**New Feature (compiler semantics/codegen):**
- Primary code: `src/semantics/` for validation changes, `src/codegen/` for runtime behavior changes.
- Tests: `tests/test_checker.py` and/or `tests/test_codegen.py` with helper wiring in `tests/utils.py`.

**New Component/Module (isolated web runner):**
- Implementation: `gsd/runner/app/` for API schemas, service orchestration, workspace management.
- Keep adapter-only logic in `gsd/` and treat `src/` modules as imported compiler core.

**Utilities:**
- Shared helpers for compiler core: `src/utils/`.
- Shared helpers for web-runner variant: `gsd/runner/app/` or `gsd/frontend/src/` (per `gsd/WEBAPP_SPEC.md`).

## Module Boundaries (Prescriptive)

- Keep grammar concerns in `src/grammar/`; do not encode grammar logic in checker/codegen.
- Keep AST shape changes in `src/utils/nodes.py` and update all phase visitors accordingly.
- Keep semantic rules in `src/semantics/static_checker.py`; codegen should assume semantically valid AST.
- Keep JVM instruction formatting in `src/codegen/emitter.py` + `src/codegen/jasmin_code.py`; keep AST traversal decisions in `src/codegen/codegen.py`.
- Keep runtime Java API signatures in sync between `src/runtime/io.java` and `src/codegen/io.py`.

## Data-Flow-Relevant Paths

- Parse/AST path: `tests/utils.py` -> `build/TyCLexer.py`, `build/TyCParser.py` -> `src/astgen/ast_generation.py`.
- Semantic path: `tests/utils.py` -> `src/semantics/static_checker.py` -> `src/semantics/static_error.py`.
- Codegen path: `tests/utils.py` -> `src/codegen/codegen.py` -> `src/codegen/emitter.py` -> `src/runtime/*.j` -> `src/runtime/*.class`.

## Extension Points for Web Runner Isolation under `gsd/`

**Compiler Orchestration Adapter:**
- Add: `gsd/runner/app/compiler_service.py`.
- Role: Wrap `ASTGeneration`, `StaticChecker`, and `CodeGenerator` stage-by-stage.

**AST Serialization Adapter:**
- Add: `gsd/runner/app/ast_serializer.py`.
- Role: Convert `src/utils/nodes.py` instances to API-safe JSON/text without changing core AST classes.

**Execution Workspace Boundary:**
- Add: `gsd/runner/app/runtime_workspace.py`.
- Role: Create per-request temp runtime dirs and avoid writing into shared `src/runtime/`.

**Limits + Safety Boundary:**
- Add: `gsd/runner/app/limits.py`.
- Role: Centralize timeout, stdout truncation, and size caps before returning API responses.

**API Contract Boundary:**
- Add: `gsd/runner/app/schemas.py`, `gsd/runner/app/main.py`.
- Role: Normalize parse/semantic/codegen/runtime errors into stable web response shapes.

## Special Directories

**`build/`:**
- Purpose: Generated ANTLR Python output imported by tests and AST generation.
- Generated: Yes.
- Committed: Yes (currently present in repository workflow).

**`reports/`:**
- Purpose: HTML test reports from `python run.py test-*` commands.
- Generated: Yes.
- Committed: No (ephemeral artifact output).

**`src/runtime/`:**
- Purpose: Runtime assets plus generated execution artifacts.
- Generated: Partially (`TyC.j`, `TyC.class` generated; `io.java`, `jasmin.jar` static assets).
- Committed: Assets yes; generated outputs typically ignored.

**`gsd/.planning/codebase/`:**
- Purpose: Planning documents consumed by GSD planner/executor.
- Generated: Yes.
- Committed: Yes (intended workflow artifacts).
