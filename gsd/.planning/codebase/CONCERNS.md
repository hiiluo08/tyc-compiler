# Codebase Concerns

**Analysis Date:** 2026-05-07

## Tech Debt

**Filesystem-coupled code generation output:**
- Issue: Code generation always emits artifacts into a shared repository directory (`src/runtime`) via `Emitter.filepath`, and generation logic is not parameterized per request/tenant.
- Files: `src/codegen/emitter.py`, `src/codegen/codegen.py`, `tests/utils.py`
- Impact: A web-compiler API can overwrite another in-flight request’s `.j`/`.class` outputs, leak output across users, and accidentally mutate repository working files in production containers.
- Fix approach: Route every compile/run request to an isolated temp workspace (per-request runtime dir), inject output path into `Emitter`, and avoid shared mutable output directories.

**Tight coupling to process CWD in execution path:**
- Issue: Runtime execution changes global process directory during compile/run.
- Files: `tests/utils.py`
- Impact: In multi-request API servers, concurrent calls can interfere with each other and with unrelated code using relative paths.
- Fix approach: Remove `os.chdir` usage and run subprocesses with explicit `cwd` only; make compiler internals path-explicit.

## Known Bugs

**Cross-request artifact deletion risk in shared runtime:**
- Symptoms: Cleanup removes all `*.j` and most `*.class` from `src/runtime` before each run.
- Files: `tests/utils.py`
- Trigger: Two requests compile simultaneously, or a long-running request overlaps with cleanup from another request.
- Workaround: Single-thread/process execution queue and strict serialization of compile/run operations.

**Potentially inconsistent generated output under concurrent requests:**
- Symptoms: One request can assemble/run classes generated by a different request due to shared `TyC.j`/`TyC.class` naming.
- Files: `src/codegen/codegen.py`, `src/codegen/emitter.py`, `tests/utils.py`
- Trigger: Parallel compile requests that target the same fixed class/file names.
- Workaround: Per-request class name and per-request isolated output directory.

## Security Considerations

**Untrusted code execution with full local process privileges:**
- Risk: Generated JVM bytecode is executed directly with host Java (`java -cp ... TyC`) and no sandboxing boundary is defined.
- Files: `tests/utils.py`
- Current mitigation: A 10-second subprocess timeout exists.
- Recommendations: Execute in hardened sandbox (container/jail), enforce CPU/memory/pid/fs/network limits, run as non-root, and disallow host filesystem write access except per-request temp dir.

**No input-size or AST-size guardrails for public API usage:**
- Risk: Crafted large inputs can consume CPU/memory during parse/check/codegen and degrade service availability.
- Files: `src/grammar/TyC.g4`, `src/astgen/ast_generation.py`, `src/semantics/static_checker.py`, `src/codegen/codegen.py`
- Current mitigation: None detected in compiler pipeline.
- Recommendations: Enforce source-size limits, parse depth/node-count limits, and request-level deadlines/cancellation.

**Toolchain invocation surface (javac/java/jasmin) exposed to user traffic:**
- Risk: Public endpoint can be abused for process-fork pressure and runtime abuse via repeated compile/run requests.
- Files: `tests/utils.py`, `run.py`, `src/runtime/jasmin.jar`
- Current mitigation: Per-subprocess timeout and captured stdout/stderr.
- Recommendations: Add rate limiting, queueing, per-user quotas, and circuit breakers around Java toolchain invocations.

## Performance Bottlenecks

**Cold compile on every request with external JVM processes:**
- Problem: Each run performs `.j` assembly and JVM startup, then executes class process.
- Files: `tests/utils.py`, `src/codegen/emitter.py`, `src/codegen/codegen.py`
- Cause: No persistent execution worker or caching strategy for repeated source/program runs.
- Improvement path: Add worker pool for isolated runners, cache toolchain readiness, and optionally cache compilation outputs by source hash.

**Disk I/O churn in shared runtime directory:**
- Problem: Frequent cleanup + regenerate cycles in `src/runtime` produce high file churn.
- Files: `tests/utils.py`, `src/codegen/emitter.py`
- Cause: Compile outputs are written to repository path, then deleted/recreated each run.
- Improvement path: Move artifacts to ephemeral temp volumes; keep repository tree immutable at runtime.

## Fragile Areas

**Codegen-to-runtime integration boundary:**
- Files: `src/codegen/io.py`, `src/semantics/static_checker.py`, `src/runtime/io.java`, `tests/utils.py`
- Why fragile: Built-in functions are duplicated across checker/codegen/runtime; mismatches can pass checking but fail at runtime.
- Safe modification: Change built-ins in all three places together and verify with focused compile+run tests.
- Test coverage: `tests/test_codegen.py` exists, but no explicit compatibility matrix test for checker/codegen/runtime built-in signature parity is detected.

**Single fixed output class naming (`TyC`) and struct class filenames:**
- Files: `src/codegen/codegen.py`, `src/codegen/emitter.py`
- Why fragile: Naming collisions are guaranteed under concurrency and can overwrite artifacts unexpectedly.
- Safe modification: Introduce deterministic unique class namespace per request/session.
- Test coverage: No concurrency tests detected in `tests/test_codegen.py` for parallel compile/run.

## Scaling Limits

**Compile/run executor model:**
- Current capacity: Effectively safe only for serialized execution because artifacts are shared under `src/runtime` and process CWD may be mutated.
- Limit: Parallel request handling breaks isolation and correctness.
- Scaling path: Stateless API tier + isolated worker pool; each job gets dedicated temp workspace and sandboxed Java process.

**Runtime time budget:**
- Current capacity: Individual subprocess timeout is set to 10 seconds for compile/assemble/run paths.
- Limit: Long or adversarial programs consume worker slots until timeout; high fan-in causes queue buildup.
- Scaling path: Queue with backpressure, stricter per-tier timeouts (parse/check/assemble/run), cancellation propagation, and per-tenant quotas.

## Dependencies at Risk

**Jasmin assembler runtime jar (`src/runtime/jasmin.jar`):**
- Risk: External binary dependency with no integrity verification step at runtime path.
- Impact: If replaced or corrupted, assembly fails or may execute unexpected behavior.
- Migration plan: Verify checksum at startup/deploy time and pin trusted artifact provenance.

**Java toolchain dependency (`java`, `javac`):**
- Risk: Runtime behavior and availability depend on host-installed Java commands.
- Impact: API instability across environments and failures when Java is missing/misconfigured.
- Migration plan: Ship pinned JRE/JDK in container image and health-check toolchain on service boot.

## Missing Critical Features

**Request-level filesystem isolation for API mode:**
- Problem: Compiler writes to repository-owned paths and cleans globally.
- Blocks: Safe multi-tenant compile/run API exposure.

**Sandbox policy and resource governance:**
- Problem: No codified sandbox/resource limits around execution of untrusted generated code.
- Blocks: Production-grade public endpoint with acceptable abuse resistance.

**API-safe execution abstraction (separate from test harness):**
- Problem: The available execution flow is in `tests/utils.py`, designed for local testing rather than server operation.
- Blocks: Clean service-layer integration with observability, retries, quotas, and structured error contracts.

## Test Coverage Gaps

**Isolation and concurrency behavior:**
- What's not tested: Parallel compile/run requests, artifact collision handling, and cross-request contamination.
- Files: `tests/test_codegen.py`, `tests/utils.py`
- Risk: Race conditions and user data leakage remain undetected until production traffic.
- Priority: High

**Security/resource-abuse scenarios:**
- What's not tested: Oversized input handling, deep nesting stress, CPU/memory abuse, and sandbox escape assumptions.
- Files: `tests/test_codegen.py`, `tests/test_checker.py`, `tests/test_parser.py`
- Risk: Public API can be DoS-prone without early warning.
- Priority: High

**Operational failure-path resilience:**
- What's not tested: Missing `java`/`javac`, corrupted `jasmin.jar`, partial artifact cleanup failure, and deterministic API error shaping.
- Files: `tests/utils.py`, `run.py`
- Risk: Inconsistent production behavior and hard-to-debug incidents.
- Priority: Medium
